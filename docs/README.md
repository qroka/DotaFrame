**Обновлено:** 13.10.2026

## 1. Начните отсюда

DotaFrame — планируемое веб-приложение для создания статичных графических публикаций по матчам Dota 2. MVP ориентирован на ручной ввод данных, готовые шаблоны и локальное хранение в браузере.

Сначала прочитайте [концепцию](research/project-brief.md), затем [границы MVP](requirements/mvp-scope.md). Продуктовая и техническая документация описывает **запланированную систему**, а не уже работающие функции.

## 3. Принятые решения для MVP

| Вопрос | Решение |
|---|---|
| Формат графики | PNG 1080 × 1080 (1:1) |
| Типы постеров | Анонс матча, результат серии, драфт Dota 2 |
| Данные | Ручной ввод; внешний API после MVP |
| Справочник | Повторно используемые Team с логотипами |
| Серии | BO3/BO5 как рабочий набор первой версии |
| Создание и редактирование матча | Отдельная страница |
| Настройка шаблона | Ограниченные готовые параметры (тема, акцент, фон) |
| Свободное перемещение элементов | Не входит |
| Хранение | IndexedDB — кандидат, требует подтверждения прототипом |
| Сохранённая публикация | Неизменяемый снимок всех отображаемых полей, включая счёт, турнир, время, команды, версии логотипов, пики/баны и портреты героев для драфта |
| PNG-экспорт | После успешного сохранения снимка |
| Бэкенд и авторизация | Не требуются в MVP |
| Резервное копирование | После MVP; о рисках локального хранения предупреждать |

Пункты, которые ранее отдельно не выбирались владельцем продукта (например, BO3/BO5 вместо BO1 или конкретные настройки оформления), являются **рабочими параметрами планирования**, а не подтверждёнными результатами пользовательского тестирования. Их можно уточнять на этапе макетов.

## 5. Что ещё не проверено

Документация подготовлена к проектированию, но техническая реализация и проверка гипотез впереди:

- HTML → PNG на реальных шрифтах, изображениях и размерах 1080 × 1080.
- Хранение Blob, миграции схемы, ограничения размера IndexedDB и восстановление после перезагрузки.
- Наличие прав на применение логотипов команд и игровых изображений.
- Пользовательские тесты времени создания анонса и результата.
- Будущие API, требования к ключам, тарифам и актуальности данных.

Эти пункты являются отдельными задачами **следующих этапов**, а не незаполненными частями текущего документационного PR.

## 6. Порядок дальнейших работ

1. Принять документационный PR и завершить [Issue #3](https://github.com/qroka/DotaFrame/issues/3).
2. Построить wireframes и UI-макеты в Figma на основе [структуры экранов](design/screen-architecture.md).
3. Выполнить технические spike по экспорту PNG и локальному хранилищу.
4. Реализовать основной сценарий с помощью HTML5, Tailwind CSS и Vanilla JavaScript.
5. Провести функциональные, визуальные и пользовательские проверки по критериям MVP.
