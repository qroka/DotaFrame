# DotaFrame — технические ограничения и план проверок MVP

**Версия:** 0.1  
**Дата:** 13.10.2026  
**Статус:** план испытаний; испытания приложения ещё не проводились  
**Связанная задача:** [#3](https://github.com/qroka/DotaFrame/issues/3)

## 1. Цель

Проверить **до полноценной разработки**, что HTML/CSS-шаблон можно стабильно экспортировать в PNG 1080 × 1080 пикселей, а локальные данные матчей и логотипы — сохранять между перезагрузками браузера без сервера.

План не означает, что прототип уже реализован: ниже критерии будущих проверок.

## 2. Исследуемая технология экспорта

**Кандидат:** [html-to-image](https://github.com/bubkoo/html-to-image) (функция `toPng`). Библиотека создаёт изображение из DOM-узла, включая стили, шрифты и изображения, используя SVG `foreignObject` и canvas.

**Ограничения:** проблемы с CORS, внешними таблицами стилей, нестандартными шрифтами и Safari; неполная совместимость CSS и больших деревьев DOM. Наличие метода `toPng` не доказывает работоспособность со всеми макетами DotaFrame.

**Допустимые альтернативы, если spike не пройден:** упрощение CSS постера; иной браузерный рендерер; ручное рисование на canvas только при обоснованной необходимости. Серверный рендеринг не входит в исходную архитектуру MVP.

## 3. Spike A — изображение 1080 × 1080

**Подготовка:** построить минимальный HTML-постер «Анонс» со специальным экспортным узлом фиксированного размера. Не создавать полноценный UI и не собирать дизайн-систему.

| ID | Проверка | Критерий прохождения |
|---|---|---|
| PNG-01 | Экспорт в Chrome | PNG создаётся и декодируется |
| PNG-02 | Фактический размер | Ровно 1080 × 1080 пикселей при `pixelRatio: 1` и согласованных настройках |
| PNG-03 | Русский и латинский текст | Текст не обрезан, кириллица корректна |
| PNG-04 | Длинные названия команд/турнира | Не выходят за безопасные границы; определён алгоритм переноса/уменьшения |
| PNG-05 | Два загруженных локально логотипа | В итоговом PNG отображаются оба изображения |
| PNG-06 | Нет логотипа | Отображается заглушка, экспорт не падает |
| PNG-07 | Шрифты | После загрузки шрифтов в PNG совпадают семейство и начертания с предпросмотром |
| PNG-08 | Настройки темы | Изменённые разрешённые цвета/фон попадают в PNG |
| PNG-09 | Элементы редактора | Кнопки и поля ввода в PNG отсутствуют |
| PNG-10 | Ошибка экспорта | Пользователь получает сообщение; сохранённая публикация не теряется |
| PNG-11 | Firefox | Тот же базовый тест набора полей и двух логотипов проходит без искажения |
| PNG-12 | Соотношение предпросмотра | Квадратный предпросмотр масштабируется без изменения экспортного размера |

**Порядок:** построить постер → дождаться `document.fonts.ready` и завершения загрузки изображений → выполнить экспорт → загрузить/открыть PNG → проверить размер и содержимое. При ошибке фиксировать браузер, версию, стек ошибки и минимальный воспроизводимый пример.

**Решение по библиотеке:** принять кандидат только после успешных PNG-01–PNG-10 и базовой проверки PNG-11; иначе документировать ограничение и повторить spike с изменённой техникой. Safari и мобильные платформы остаются за пределами первого обязательного набора, пока не проверены.

## 4. Spike B — хранение в IndexedDB

Кандидат на хранилище: [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API). Она может хранить структурированные объекты и Blob.

| ID | Проверка | Критерий прохождения |
|---|---|---|
| DB-01 | Создание двух команд | Разные ID, нет дубликата при повторном использовании |
| DB-02 | Запись логотипа как Blob | Файл сохраняется и декодируется после перезагрузки |
| DB-03 | Создание серии | `teamAId` и `teamBId` ссылаются на разные существующие команды |
| DB-04 | Создание сохранённого PosterProject | Все отображаемые поля и настройки фиксируются в `dataSnapshot` |
| DB-05 | Изменение исходных данных | Старый PosterProject не меняется, новый получает актуальные значения |
| DB-06 | Смена логотипа | Старый PosterProject использует старый MediaAsset, новая публикация — новый |
| DB-07 | Ошибка транзакции | Пользователь видит ошибку, существующие данные не исчезают |
| DB-08 | Недостаточно места | `QuotaExceededError` обрабатывается; нет сообщения об успешном сохранении |
| DB-09 | Миграция схемы | После обновления версии базы существующие записи остаются читаемыми |

**Проверить хранилище:** после закрытия/открытия вкладки, перезагрузки страницы и обновления кода приложения. Данные в приватном режиме и после ручной очистки браузера не гарантируются — это пользовательское ограничение, которое надо показать в интерфейсе.

## 5. Spike C — исторический снимок

Проверить сквозной сценарий:

1. Создать условную серию Team A — Team B, турнир «Test Cup», время и формат BO3.
2. Сохранить анонс и экспортировать PNG.
3. Изменить имя и логотип Team A, название турнира и время начала.
4. Открыть **старый** PosterProject: увидеть неизменные название, логотип, турнир и время.
5. Создать **новый** постер на базе серии: увидеть обновлённые данные.
6. После завершения серии сохранить результат 2:1, экспортировать PNG.
7. Исправить исходный счёт на 2:0 и проверить: исторический результат 2:1 остался неизменным, новый постер показывает 2:0.

Для этого в `PosterProject` нужны `dataSnapshot`, `styleOptions`, `templateRevision`, а версии MediaAsset должны оставаться доступными. Без сохранённой версии шаблона нельзя гарантировать идентичный повторный экспорт после переработки CSS.

## 6. Риски и смягчающие меры

| Риск | Вероятное проявление | Действие |
|---|---|---|
| CORS и сторонние изображения | Пустой логотип в PNG | Для MVP использовать сохранённые локально медиафайлы |
| Неожиданное масштабирование | PNG другого размера | Явно задать экспортный размер и pixelRatio; проверить свойства PNG |
| Шрифты и CSS эффекты | Отличие PNG от предпросмотра | Локальные/разрешённые ресурсы; простые проверенные стили |
| Ограничения IndexedDB | Данные не сохранились | Обработка ошибок транзакций, контроль статуса сохранения |
| Очистка браузера | Потеря проектов | Предупреждение; будущая резервная копия |
| Изменение логотипов | История публикаций нарушена | Неизменяемые версии MediaAsset и ссылки из snapshot |
| Изменение шаблонов | Старый постер экспортируется иначе | Сохранять templateRevision и проверять обратную совместимость |
| Юридические ограничения на логотипы | Невозможность публичного использования | Проверка прав на активы до публикации примеров |

## 7. Результат проверки

Для каждого spike создаётся запись: конфигурация браузера, минимальный тест, фактический результат, скриншот/пример PNG, вывод «пройдено / не пройдено», номер Issue/PR с исправлением при необходимости.

**На 13.10.2026 тестов и подтверждённых метрик нет.** До прохождения spike нельзя заявлять, что сохранение Blob и HTML → PNG уже работают в DotaFrame.
