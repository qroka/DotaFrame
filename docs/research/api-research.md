# DotaFrame — исследование источников данных Dota 2

**Версия:** 0.1  
**Дата изучения публичной документации:** 13.10.2026  
**Статус:** сравнительный технический анализ, без подключённых API и без выполненных запросов  
**Связанная задача:** [#3](https://github.com/qroka/DotaFrame/issues/3)

## 1. Что требуется продукту

В будущем DotaFrame может автоматически заполнять турнир, команды, дату/время, формат серии, итоговый счёт и драфты карт. В MVP ручной драфт уже предусмотрен, автоматический импорт — нет.

**Для MVP данные вводятся вручную.** Отсутствие доступа к внешним API не должно блокировать создание постеров или повторное использование справочника команд.

При оценке источника особенно важны:

1. Наличие **серий профессиональных матчей** (BO3/BO5) и расписания, а не только отдельного игрового `match_id`.
2. Лицензионные условия и разрешение на использование данных и изображений.
3. Доступность тарифа, лимиты запросов и требования к аутентификации.
4. Надёжность и своевременность обновления расписания/счёта.
5. Возможность безопасной интеграции без раскрытия токенов в публичном браузерном приложении.

## 2. Рассмотренные источники

### 2.1. PandaScore

**Официальные источники:**
- [Обзор API](https://developers.pandascore.co/docs/introduction)
- [Доступность функций по тарифам](https://developers.pandascore.co/docs/plan-reference)
- [Начало работы](https://developers.pandascore.co/docs/getting-started)
- [Тарифы](https://www.pandascore.co/pricing)
- [FAQ о безопасном вызове API](https://developers.pandascore.co/docs/frequently-asked-questions)

PandaScore публикует API по киберспортивным матчам. В документации по Dota 2 указаны списки предстоящих, прошедших и текущих матчей: `GET /dota2/matches/upcoming`, `/past`, `/running`. По состоянию на дату исследования общие данные расписания и результатов входят в free/fixtures-категорию. Запросы детальных данных о конкретном матче, картах и статистике могут требовать платных тарифов. Действующие условия следует проверять непосредственно перед интеграцией.

**Плюсы:** модель данных близка предметной области DotaFrame; есть сведения о расписании, командах и турнирных матчах. **Минусы:** токен, квоты, ограничения тарифов и потенциальные ограничения на логотипы/изображения.

**Важный нюанс:** поставщик в FAQ рекомендует **серверный прокси** для безопасных API-запросов. Публичный клиент не должен содержать приватный API-токен. Следовательно, полноценную автоматическую интеграцию с токеном нужно планировать после MVP — с отдельным серверным компонентом или иным согласованным способом защиты учётных данных.

### 2.2. OpenDota

**Официальные источники:**
- [OpenDota API](https://opendota.apidocumentation.com/)
- [OpenDota GitHub](https://github.com/odota/core)

OpenDota предоставляет данные Dota 2, в том числе разбор отдельных матчей: например, `GET /matches/{match_id}`. Документация описывает бесплатные лимиты на обращения, однако они могут изменяться и не являются основанием для архитектурного обещания без проверки.

**Плюсы:** подробные игровые сведения, доступ к отдельным игровым матчам и данным героев. **Ограничение:** одиночный Dota 2 match ID не равнозначен киберспортивной серии BO3/BO5 и её расписанию. Для соответствия продукта модели MatchSeries требуется проверенная связка игр с турниром и серией — одного эндпоинта отдельного матча недостаточно.

**Вывод:** OpenDota целесообразно исследовать для отдельных карт, драфтов и послематчевых деталей **после MVP**, а не считать основным источником расписания профессиональных серий по умолчанию.

### 2.3. Ручной ввод

**Плюсы:** не требует регистрации, внешнего токена, квоты или серверной части; редактор контролирует правильность данных, создаёт тестовые серии и постеры даже офлайн после загрузки приложения.

**Минусы:** человек может допустить опечатку, пропустить перенос начала игры или ввести неверный результат.

**Решение для MVP:** ручной ввод — единственный обязательный путь. Нужны проверка обязательных полей, справочник команд и понятные ошибки счёта.

## 3. Сравнение

| Критерий | Ручной ввод | PandaScore | OpenDota |
|---|---|---|---|
| Серии и расписание про-турниров | Пользователь вводит | Заявлена предметная модель матчей и расписаний | Требует дополнительного анализа |
| Результат серии | Пользователь вводит | Доступны результаты в fixtures | Нужно агрегировать игры |
| Результат и статистика отдельной карты | Не входит в MVP | Детальная информация зависит от тарифа | Отдельные match IDs и статистика |
| Ручные драфты / автоимпорт | Ручной ввод в MVP; автоимпорт после | Требует проверки конкретных полей и тарифов | Потенциальный источник данных матчей |
| Токен в публичном frontend | Нет | Не должен размещаться | Условия аутентификации/лимитов требуют проверки |
| Зависимость от внешнего сервиса в MVP | Нет | Да при интеграции | Да при интеграции |

Неотмеченная интеграция и потенциальные возможности не являются подтверждением, что нужные поля уже проверены на реальном ответе API.

## 4. Предварительное решение

1. **MVP:** ручной ввод матчей и драфтов карт, локальный каталог героев, отсутствие сетевых API для матчей и драфтов.
2. **После MVP:** провести прототип PandaScore с тестовым доступом и замером реального покрытия матчей/турниров; выяснить ограничения лицензии.
3. При запросе деталей отдельных карт исследовать OpenDota, не предполагая автоматическую привязку игрового `match_id` к BO-серии.
4. Спроектировать отдельный адаптер источников данных, чтобы UI и шаблоны не зависели от формата ответа одного поставщика.
5. Сохранять **источник и время последнего обновления** автоматически полученных данных в будущей версии, но при сохранении публикации всё равно фиксировать независимый `dataSnapshot`.

## 5. Что необходимо проверить перед любой интеграцией

- Создание и хранение ключа доступа; CORS; условия публичного отображения статистики и логотипов.
- Актуальные цены, квоты, региональную доступность, ограничения коммерческого использования.
- Корректность timezone и однозначность дат.
- Соответствие участников, турнира, счёта и отдельных карт.
- Источники ошибок и действия при rate limit, недоступном API или отменённом матче.

## 6. Статус исследования

**Выполнено:** обзор официальной документации и предварительный выбор направления.  
**Не выполнено:** реальная авторизация, сетевые запросы к API, проверка покрытия матчей, лицензий изображений и качества данных.

Ни один внешний API не включается в состав MVP без отдельного согласования.
