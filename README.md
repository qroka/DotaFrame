# DotaFrame

**DotaFrame** — веб-приложение для создания графических публикаций о киберспортивных матчах Dota 2 на основе готовых шаблонов.

Проект ориентирован на SMM-специалистов киберспортивных команд, редакторов профильных СМИ и администраторов тематических сообществ.

> **Статус:** предпроектный анализ. Описанные ниже функции являются планами разработки, а не возможностями уже работающего приложения.

## Зачем нужен DotaFrame

При освещении турниров редакторам приходится регулярно готовить анонсы матчей, сообщения о начале игр, драфты и результаты. При использовании универсальных графических редакторов одни и те же данные о командах и турнирах могут вводиться повторно.

**Идея DotaFrame:** хранить данные матча отдельно от оформления, чтобы на основе одной серии создавать несколько графических публикаций в едином стиле.

Предполагаемый рабочий процесс:

1. Создать матч и заполнить информацию о командах, турнире и времени начала.
2. Выбрать готовый графический шаблон.
3. Настроить предусмотренные шаблоном параметры оформления.
4. Проверить изображение в предпросмотре.
5. Скачать готовый PNG.
6. Позднее открыть тот же матч, указать результат и создать новую публикацию без повторного ввода общих данных.

## Планируемый MVP

Первая версия сосредоточена на генерации изображений **без свободного графического редактора**.

| Возможность | План MVP |
|---|---|
| Ручное создание и редактирование матчей | Да |
| Информация о командах, турнире, дате и формате серии | Да |
| Загрузка логотипов команд | Да |
| Готовые шаблоны «Анонс матча», «Результат серии» и «Драфт Dota 2» | Да |
| Ручной выбор героев и банов карты | Да |
| Настройка доступных цветов, фона и текста | Да |
| Предпросмотр публикации | Да |
| Экспорт изображения в PNG | Да |
| Локальное сохранение данных проекта | Да |
| Свободное перемещение объектов на изображении | Нет |
| Обязательная регистрация или серверная часть | Нет |
| Автоматическая загрузка матчей через API | Нет |

Подробные сценарии, требования и критерии готовности описаны в [документации](docs/README.md). Для MVP принят рабочий набор форматов **BO3 и BO5**; пользователь создаёт/редактирует матч на отдельной странице.

## Дальнейшее развитие

После MVP планируется исследовать и при необходимости реализовать:

- графику «Матчи сегодня» и «Матч начинается»;
- автоматическое получение драфтов и результаты отдельных карт;
- автоматическое получение расписания и результатов матчей через API;
- дополнительные размеры и форматы для социальных сетей;
- сохранённые фирменные стили;
- пакетную генерацию публикаций;
- расширенные инструменты настройки шаблонов.

Эти функции **не входят в первоначальный объём разработки**.

## Предварительный технологический стек

| Инструмент | Назначение |
|---|---|
| HTML5 | Разметка приложения и шаблонов изображений |
| Tailwind CSS | Стили интерфейса |
| JavaScript (Vanilla JS) | Логика, работа с данными и предпросмотр |
| Браузерная библиотека экспорта HTML в PNG | Генерация изображений; выбор будет проверен на прототипе |
| Figma | Дизайн-система, интерфейс и графические шаблоны |
| Git и GitHub | Контроль версий и организация разработки |

Для MVP рассматривается работа без обязательного бэкенда и платных API.

## Этапы разработки

1. **Предпроектный анализ** — проблема, аудитория, конкуренты, сценарии и границы MVP.
2. **Проектирование** — функциональные требования, модель данных и архитектура.
3. **UX/UI-дизайн в Figma** — интерфейс генератора, дизайн-система и шаблоны публикаций.
4. **Разработка MVP** — ввод данных, шаблоны, предпросмотр, сохранение и экспорт PNG.
5. **Тестирование** — проверка сценариев, корректности графики и удобства работы.
6. **Публикация и развитие** — развёртывание и последующие функции.
