# Стартовый промт для новой сессии

Скопируйте блок ниже в новую сессию Claude Code, открытую в папке проекта.

```text
Ты работаешь над проектом DotaFrame (Nuxt 4 + Nuxt UI 4 + SQLite через node:sqlite, редактор постеров по Dota 2).
Сначала прочитай docs/audit-and-plan.md — там аудит и план доработки. Затем README.md и docs/architecture/.

Контекст:
- Проект мигрировал с vanilla JS + IndexedDB (src/) на Nuxt + SQLite (app/, server/), но миграция не завершена: src/data/* (IndexedDB) всё ещё импортируется рендером, есть дубли src/editor/projectFactory.js и app/services/projectFactory.ts.
- Рендер постеров (src/render, src/templates, src/domain) — рабочая логика, её поведение менять нельзя без тестов.

Правила работы:
1. Идём строго по шагам плана из docs/audit-and-plan.md, один шаг за раз. Перед каждым шагом коротко скажи, что собираешься менять.
2. Перед правками запусти `npm test` и зафиксируй исходное состояние тестов; после каждого шага запускай `npm test` и `npm run typecheck`.
3. Не удаляй файлы, не проверив, что на них нет импортов (grep). Удаление src/data/* делай только после переноса зависимостей.
4. Не трогай данные в SQLite и не меняй схему без резервной копии и отдельного согласования.
5. Коммиты — маленькие, по одному логическому изменению; не пушить без моей просьбы.
6. Если что-то из плана противоречит коду — остановись и спроси.

Начни с шага 1 («Гигиена репозитория»): покажи список того, что собираешься удалить или изменить (файлы `* 2.js`, dist/, package-lock.json, skills-lock.json, .claude/skills/), и дождись моего подтверждения.

Важно: я пока не назвал, что именно мне не нравится в системе. Если я напишу это в ходе работы, пересмотри приоритеты плана под мои замечания.
```
