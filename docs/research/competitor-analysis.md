# DotaFrame — анализ конкурентов

**Версия:** 0.2  
**Статус:** Исследование по открытой документации; практическая проверка интерфейсов — следующий этап  
**Дата проверки источников:** 13.10.2026  
**Связанная задача:** #3

## 1. Цель и методика исследования

Цель — определить, как существующие сервисы создают графику для публикаций о спортивных и киберспортивных матчах, и выделить обоснованные требования к DotaFrame.

Метод исследования: анализ официальных страниц продуктов, справочных материалов и заявленных сценариев использования. Рассматриваются шаблоны, повторное использование данных, настройки оформления, экспорт и ограничения доступа.

**Ограничение исследования:** авторизованные интерфейсы конкурентов не проходились, тестовые проекты не создавались, время выполнения действий не измерялось. Поэтому характеристики удобства и числа шагов не считаются подтверждёнными экспериментально. Отсутствие сведений на сайте не доказывает отсутствие функции.

## 4. Анализ продуктов

### 4.1. Canva

**Подтверждено:** доступны шаблоны социальных публикаций, редактирование текста, цветов и изображений [S1], экспорт PNG [S3]. Отдельная функция Bulk Create связывает поля табличных данных с текстовыми и графическими элементами и позволяет формировать серию вариантов; её использование ограничено соответствующими тарифами [S2].

**Сильные стороны:** свобода композиции, большой выбор графических решений, массовое создание вариантов из данных.

**Что не подтверждено:** готовая модель «турнир → серия BO3/BO5 → карта → драфт → публикация», автоматически связанная с данными матчей Dota 2.

**Вывод для DotaFrame:** нельзя считать массовую генерацию уникальной функцией. Следует сократить необходимость предварительно настраивать таблицу и вручную связывать поля: пользователь выбирает матч и сразу получает доступные шаблоны.

### 4.2. ParaScores Graphics Studio

**Подтверждено:** сервис использует данные турнира и создаёт графику результатов, таблиц, сеток и расписания игрового дня с экспортом PNG [S4]. Официальное описание предполагает последовательность «выбрать вид графики → выбрать матч/тур/группу → скачать изображение». Заявлена серверная генерация и автоматическая подстановка фирменных данных турнира и спонсоров.

**Сильные стороны:** структурированные данные не вводятся повторно при каждой публикации; минимальное число настроек после подготовки турнира.

**Ограничения применимости:** официальный пример и атрибуты вроде авторов голов ориентированы на традиционный спорт. Поддержка драфтов героев, результатов отдельных карт Dota 2 и структуры BO3/BO5 на проверенной странице не подтверждена.

**Вывод для DotaFrame:** повторить принцип разделения данных и шаблонов; модель должна учитывать серию и отдельные карты, а не только единичный матч.

### 4.3. FLM System

**Подтверждено:** создаёт анонсы, результаты с авторами голов и общую графику тура на основании уже сохранённых данных лиги; предусматривает стили classic, paper и dark и экспорт PNG [S5]. Заявлен 14-дневный пробный период.

**Сильные стороны:** повторное использование информации и сохранение единообразного визуального стиля.

**Ограничения применимости:** продукт встроен в систему управления спортивной лигой, а атрибуты результата ориентированы на соответствующие виды спорта. Сценарии публикации драфтов Dota 2 и карт серии на проверенной странице не подтверждены.

**Вывод для DotaFrame:** простой редактор с преднастроенными шаблонами может быть полезнее свободного графического редактора, если задача — регулярно публиковать однотипные сообщения.

### 4.4. LHM Ultra Dota 2 HUD

**Подтверждено:** система предоставляет графику драфта с интеграцией в Dota 2, предматчевые и послематчевые оверлеи, а также сохранение пресетов оформления в LHM Cloud [S6]. Ultra доступен в Professional / Enterprise [S6].

**Сильные стороны:** специальная терминология и рабочий процесс Dota 2, включая переход от драфта к завершению матча.

**Отличие от DotaFrame:** основная сфера LHM — прямой эфир и трансляционные оверлеи. На изученных страницах не подтверждён отдельный сценарий экспорта готовых статичных PNG-публикаций для социальных сетей.

**Вывод для DotaFrame:** структуру «до матча → драфт → карта → итог серии» стоит считать важной моделью предметной области, но не копировать трансляционный интерфейс и его сложность.

## 5. Разбор общего пользовательского сценария

**Сценарий:** редактор готовит анонс Team Spirit — Team Liquid, затем после завершения BO3 выпускает пост с итоговым счётом. Команды здесь используются как условные участники сценария; конкретный матч и результаты не утверждаются.

| Продукт | Путь по официальной документации | Проверка на практике |
|---|---|---|
| Canva | Выбрать шаблон → заполнить названия и изображения → экспортировать PNG. При Bulk Create можно предварительно связать табличные поля с макетом [S1–S3]. | Не проводилась |
| ParaScores | Создать/открыть турнир с данными → выбрать вид графики и матч/тур → скачать PNG [S4]. | Не проводилась |
| FLM System | Вести матч в системе лиги → выбрать предустановленный стиль → скачать изображение в разделе Social Media [S5]. | Не проводилась |
| LHM | Подготовить данные матча и пресеты → использовать pre/post-match и draft-оверлеи в процессе трансляции [S6]. | Не проводилась |

**Нельзя утверждать по этой таблице**, что какой-то продукт объективно быстрее других: длительность действий не измерена. Сходство официальных сценариев показывает, что повторное использование матчевых данных уже реализовано у конкурентов.

Для будущего практического теста: выполнить одинаковый сценарий для доступных сервисов; зафиксировать регистрацию, число действий, возможность повторного использования данных, доступность PNG, затраченное время и ограничения бесплатного доступа. Отдельно проверить доступность сервисов из РФ. Невозможность протестировать функцию отмечать как «не проверено», а не «нет функции».

## 6. Выводы для проектирования DotaFrame

### 6.1. Вывод о конкуренции

Проблема регулярной генерации спортивной графики уже решается существующими сервисами. Поэтому ценностное предложение DotaFrame не должно строиться на утверждении, что конкуренты не умеют делать шаблоны, PNG или массовую генерацию.

**Рабочая гипотеза позиционирования:** DotaFrame — простой генератор *статичных изображений для SMM Dota 2*, организованный вокруг серии BO3/BO5 и её карт, с последовательными типами публикаций.

### 6.2. Проектные решения

| Решение | Обоснование | Этап |
|---|---|---|
| Данные серии хранятся отдельно от шаблонов | Избежать повторного ввода, как в ParaScores/FLM | MVP |
| Шаблоны вместо свободного перемещения элементов | Сократить сложность и число операций | MVP |
| Ручной ввод с последующей возможностью API | Не блокировать первую версию платными источниками | MVP → далее |
| Анонс и итог серии — первые два шаблона | Проверить базовый путь «до/после матча» | MVP |
| Драфт, LIVE и результат отдельной карты | Проверить специфическую ценность для Dota 2 | После MVP |
| Отдельные форматы для соцсетей и пакетная генерация | Повысить удобство SMM-процесса | После MVP |
| Локальное сохранение введённых матчей | Пользователь не должен заполнять команду/турнир заново | MVP |

### 6.3. Неподтверждённые гипотезы

- SMM-специалист создаст публикацию быстрее, чем в универсальном редакторе.
- Шаблоны Dota 2 будут удобнее универсальной спортивной графики.
- Повторное использование серии и данных карт уменьшит число ошибок при публикациях.
- Пользователи готовы работать с отдельным генератором вместо привычного Canva.

Эти гипотезы следует проверять через прототип, измерение времени создания публикаций и обратную связь потенциальных пользователей.
