# DotaFrame — границы MVP и критерии готовности

**Версия:** 0.6  
**Статус:** Черновик на согласование  
**Связанная задача:** [#3](https://github.com/qroka/DotaFrame/issues/3)

## 1. Цель первой версии

Проверить основной пользовательский сценарий: редактор вводит данные серии Dota 2 один раз, создаёт анонс, затем по окончании серии обновляет счёт и получает второе изображение из другого готового шаблона. Дополнительно редактор вручную заполняет драфт отдельной карты BO3/BO5 и создаёт третий тип графики.

**MVP проверяет техническую осуществимость и удобство рабочего процесса; он ещё не доказывает экономию времени по сравнению с конкурентами.**

## 2. Что входит

| Функция | В MVP | Примечание |
|---|---|---|
| Ручной ввод и изменение матча | Да | Отдельная страница, турнир, дата/время, формат BO3/BO5 |
| Справочник команд | Да | Название, необязательный логотип, повторное использование в сериях |
| Логотипы команд | Да | Локальная загрузка в запись команды |
| Неизменные сохранённые публикации | Да | Снимок всех отображаемых данных и оформления, включая версии логотипов |

| Шаблон «Результат серии» | Да | Финальный счёт |
| Шаблон «Драфт Dota 2» | Да | Ручное заполнение пиков, банов и сторон выбранной карты |

## 3. Плановая компоновка

Для первой версии утверждён единый квадратный формат **1080 × 1080 пикселей (1:1)** для всех трёх шаблонов — «Анонс матча», «Результат серии» и «Драфт Dota 2». Композиция фиксированная; допустимые варианты цвета, фона и типографики определяются шаблоном. Дополнительные размеры и адаптации для Stories отложены на следующие версии.

Рендеринг и экспорт выполняются в браузере. Конкретная библиотека должна пройти технический эксперимент с кириллицей, шрифтами, логотипами и длинными названиями.

## 4. Основной сквозной тест

**Подготовка анонса:**

1. Добавить Team A и Team B в справочник (при желании загрузить логотипы), затем создать между ними серию BO3 с названием турнира и временем.
2. Убедиться, что выбранные команды и их логотипы подставлены из справочника.
3. Выбрать «Анонс матча», настроить оформление и сохранить публикацию со снимком всех отображаемых данных.
4. Убедиться, что название, дата и логотипы отображаются корректно.
5. Скачать PNG и проверить фактический размер 1080 × 1080 пикселей.

**Подготовка результата той же серии:**

1. Повторно открыть сохранённый матч после перезагрузки страницы.
2. Ввести корректный финальный счёт 2:1.
3. Выбрать «Результат серии» и сохранить новую публикацию с актуальным снимком всей серии.
4. Проверить, что общие данные подставились автоматически, а победитель определён правильно.
5. Скачать второй PNG; убедиться, что данные для анонса не нужно вводить заново.

**Подготовка драфта одной карты:** выбрать серию и номер карты, назначить Radiant/Dire, вручную выбрать по пять героев для каждой стороны и баны, проверить предварительный вид → сохранить неизменный снимок → скачать PNG 1080 × 1080.

**Негативные проверки:** пустое название команды, некорректный счёт 3:0 для BO3, очень длинное название, повреждённое изображение, ошибка сохранения, ошибка экспорта, повторяющийся герой, незаполненные пики, неверный номер карты. До успешного сохранения PosterProject экспорт недоступен.

## 5. Definition of Done

- [ ] Три сценария (анонс, результат серии и драфт карты) работают от начала до конца.
- [ ] Переключение шаблонов не удаляет введённые данные матча.
- [ ] Одна запись команды используется в нескольких матчах без дублирования названия и логотипа.
- [ ] После переименования команды, смены логотипа и изменения счёта/времени/турнира старый PosterProject отображает сохранённые значения, а новый — актуальные.
- [ ] Исторические медиафайлы сохраняются после замены текущего логотипа.
- [ ] Локально сохранённый проект восстанавливается после перезагрузки, а исходные данные, изменённые позднее, не меняют его содержимое.
- [ ] Все три шаблона экспортируют PNG размером 1080 × 1080 пикселей без элементов интерфейса **после сохранения** снимка.
- [ ] Драфт сохраняет Radiant/Dire, 5 пиков на команду, баны и номер карты; проверяется уникальность героев и историческая неизменность портретов.
- [ ] Длинные названия и отсутствие логотипа не ломают композицию.
- [ ] Ошибки ввода и экспорта объясняются пользователю.
- [ ] Основной сценарий проверен в заранее выбранных настольных браузерах.
- [ ] Дизайн и требования для реально реализованных функций согласованы.
- [ ] Документация и инструкции запуска находятся в репозитории.

## 6. Что исследуем после работающего прототипа

Тестирование с потенциальными пользователями: подготовка анонса и результата в DotaFrame и привычном инструменте. Измеряются время, число действий, доля ошибок и субъективная удобность. Без такого сравнения нельзя утверждать, что DotaFrame экономит время.

## 7. Рабочие решения для MVP и уточнения дизайна

Для подготовки Figma и первого прототипа приняты следующие **проектные настройки** (могут быть пересмотрены после проверки интерфейса; они не требуют отдельного подтверждения пользователя на этом этапе):

- **Форматы серий:** BO3 и BO5. Поддержка BO1 и технических результатов отложена.
- **Создание и редактирование матча:** отдельная страница, выбор команд из справочника.
- **Оформление:** предустановленная тема, акцентный цвет и фон по ограниченным настройкам; без перемещения блоков и загрузки произвольного шрифта.
- **Драфт:** третий шаблон MVP; ручной выбор героев из каталога и данные отдельной карты (только драфт, без результата карты). Подробности — [спецификация генератора драфтов](draft-generator.md).
- **Публикация:** сначала сохранить неизменный снимок, затем экспортировать PNG; просмотр сохранённого снимка — без прямого редактирования. Для исправлений создавать новый постер.
- **Часовой пояс:** явно отображать и сохранять идентификатор часового пояса; не допускать неоднозначного времени в снимке.
- **Хранилище:** IndexedDB как выбранный кандидат, принятие по результатам технического spike; исторические версии логотипов сохраняются.
- **Браузеры первого теста:** актуальные настольные Chrome и Firefox; Edge — дополнительная проверка, мобильная версия не обещается.
- **Резервное копирование:** в MVP не включено. Пользователь предупреждён о возможной потере локальных данных.

**Открытые детали для wireframes:** отступы и перенос названий внутри постера, конкретная палитра и пресеты фона, композиция формы. Они не расширяют функциональные границы MVP.
