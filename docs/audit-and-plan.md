# DotaFrame — аудит и план доработки

Дата аудита: 2026-11-12. Основан на чтении кода и документации; сборка и тесты не запускались.

## 1. Главные недостатки

### 1.1 Две параллельные архитектуры (миграция не закончена)
- `src/data/{db,repos,media,backup}.js` — старый слой IndexedDB — остался в репозитории. Рендер всё ещё зависит от него: `src/render/renderPoster.js` импортирует `collectAssetRefs` из `src/data/media.js`, а тот тянет `db.js`.
- `src/editor/projectFactory.js` дублирует `app/services/projectFactory.ts`.
- ~3800 строк JS в `src/` без типов; `allowJs` + `checkJs: false` стирают типизацию на границе с `app/` и `server/`.
- `nitro.externals.inline: [/\/src\//]` — обходной путь ради импорта `src/` на сервере.
- `dev/poster-lab.*` — устаревшая песочница.

### 1.2 Документация и тесты устарели
- `docs/architecture/system-overview.md` описывает vanilla JS + IndexedDB; `docs/requirements/mvp-scope.md` говорит, что бэкапа нет и формат один (1080×1080) — README говорит обратное.
- В git лежат дубли `tests/e2e/data.spec 2.js`, `editor.spec 2.js`, `helpers 2.js`; `data.spec 2.js` тестирует старый IndexedDB-слой.
- `dist/` — устаревший артефакт; `package-lock.json` изменён и не закоммичен; `skills-lock.json` и `.claude/skills/` не отслеживаются.

### 1.3 Серверный слой
- `server/utils/repository.ts`, `database.ts`: SQL и маппинг в строках по 300+ символов — тяжело читать и ревьюить.
- `team()` / `match()` делают запрос на каждую строку (N+1).
- `/api/bootstrap` отдаёт всё, включая полные `data_json` / `style_json` публикаций.
- Схема описана трижды: миграции, `columns` в `backup.post.ts`, `tables` в `backup.get.ts`.

### 1.4 Бэкап и данные
- Бэкап — один JSON с base64 всех картинок, собирается целиком в памяти.
- Восстановление — upsert без проверки строк по схеме; `version` пишется, но не проверяется.
- Нет сборки мусора для `media` (старые логотипы остаются).
- Лимит «до 30 версий» публикации реализован (`repository.ts`, удаление старых ревизий при сохранении); проверено. GC для `media` по-прежнему нет.

### 1.5 Безопасность
- `/api/media/[id]` отдаёт SVG с исходным `Content-Type` без `nosniff` и `Content-Security-Policy` → скрипт в открытом SVG выполнится на origin приложения.
- Тип файла берётся из заявленного `file.type`, без проверки сигнатуры (в старом `media.js` была `sniffImageType`).
- Нет авторизации/CSRF; `/api/backup` отдаёт всю базу любому, кто достучится до порта. Для локального инструмента допустимо, но сервер нужно явно привязать к `127.0.0.1` и описать это в README.

### 1.6 Редактор
- `EditorWorkspace.vue` совмещает загрузку, сохранение, экспорт, переключение шаблонов, горячие клавиши; много `as any`.
- `dirty` считается через `JSON.stringify(state)` на каждое изменение.
- Undo/Redo заявлен в README, но в новом `EditorWorkspace` его нет (логика осталась в `src/editor/store.js`).
- Предпросмотр полностью пересобирает DOM и ждёт шрифты/картинки при каждом изменении.
- `defineShortcuts({ meta_s })` — проверить, что на Windows это Ctrl+S.

### 1.7 Прочее
- `ssr: false`: Nuxt используется как SPA + API — допустимо, но стоит зафиксировать решение.
- README: «без API-ключей», при этом интеграции PandaScore/OpenDota требуют токенов в `.env`.
- 126 PNG героев (8,6 МБ) в `public/` и git.
