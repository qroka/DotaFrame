# DotaFrame

**DotaFrame** — браузерный редактор киберспортивной графики по Dota 2 для SMM-специалистов, редакторов и дизайнеров сообществ.

Данные матча вводятся **один раз**, затем из них делаются разные публикации: анонс, афиша игрового дня, WIN / LOSE, итог серии, драфт карты. Каждая сохранённая публикация хранит **собственный снимок данных**, поэтому смена логотипа команды или исправление счёта не меняет уже выпущенные постеры.

Приложение работает полностью локально: без сервера, регистрации и API-ключей. Все данные и изображения хранятся в IndexedDB браузера.

## Что работает

- **Справочник команд**: название, короткое название, регион, заметки, логотип (PNG/JPEG/WebP/GIF/SVG). Есть поиск, редактирование, замена и удаление логотипа. Удалить команду, которая используется в матчах, нельзя.
- **Матчи и серии**: две разные команды, турнир, стадия, дата, время, часовой пояс, BO1/BO2/BO3/BO5, статус, счёт. Счёт проверяется по формату: для BO2 допускается 1:1, для BO3 и BO5 — нужное число побед. Список матчей с поиском и фильтрами, множественный выбор для афиши игрового дня.
- **Шесть шаблонов** в общей дизайн-системе: Match Announcement, Matchday (1–6 матчей), WIN, LOSE, Series Result, Dota Draft.
- **Редактор публикации**: панель данных, библиотека шаблонов, живой предпросмотр с масштабом, панель оформления.
  - Оформление: темы, акцентный цвет и цвет текста, фон-пресет или своё фото (масштаб, позиция, размытие, яркость, обесцвечивание), затемнение, градиент, изображение игрока или персонажа, шрифты Roboto Flex / Oswald / Unbounded / Inter с весом, наклоном и шириной, видимость элементов, подписи соцсетей.
  - Undo/redo, горячие клавиши, сброс оформления, предупреждение о несохранённых изменениях.
  - Проверка макета: автоподгонка текста, предупреждения о непомещающемся тексте, ошибки данных (например, WIN для проигравшей команды или больше 6 матчей в афише).
- **Генератор драфтов**: выбор матча и карты, Radiant/Dire, по 5 пиков, переменные списки банов (0–10 на сторону), каталог из 126 героев с поиском, в том числе по русским названиям и сокращениям. Проверяется уникальность героев. Драфт карты сохраняется (один на пару «матч + карта»).
- **Публикации и история**: галерея с превью, дублирование, удаление с подтверждением, повторный экспорт. У каждой публикации до 30 неизменяемых версий; любую можно экспортировать или восстановить.
- **Экспорт PNG** 1080 × 1080 и 1280 × 1280. Размер задаётся конфигурацией шаблона. Реальный размер PNG проверяется после экспорта. Шрифты встраиваются из локальных файлов, CDN не нужен.
- **Резервная копия**: один JSON со всеми данными и изображениями. Восстановление в режиме «объединить» или «заменить» с проверкой формата. Есть очистка неиспользуемых изображений и запрос постоянного хранения.
- **Портреты героев**: локальный набор с массовым импортом и автоматическим сопоставлением файлов героям по имени.

## Установка и запуск

Нужны Node.js 20+ и npm.

```bash
git clone https://github.com/qroka/DotaFrame.git
cd DotaFrame
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173/`).

| Команда | Назначение |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | production-сборка в `dist/` |
| `npm run preview` | просмотр собранной версии |
| `npm test` | юнит-тесты (Vitest) |
| `npm run test:e2e` | сквозные и визуальные тесты (Playwright, Chromium + Firefox) |
| `npm run test:all` | все тесты |

Перед первым запуском e2e установите браузеры: `npx playwright install chromium firefox`.

## Как пользоваться

1. **Команды → Добавить команду**: название и, при желании, логотип.
2. **Матчи → Создать матч**: команды, турнир, время, формат. После игры укажите статус «Завершён» и счёт.
3. В строке матча нажмите **«Создать публикацию»** и выберите шаблон. Можно начать и со страницы **Шаблоны**.
4. Настройте оформление справа, тексты и данные слева. Нажмите **Сохранить** (Ctrl+S).
5. **PNG** (Ctrl+Shift+E) скачивает изображение. Перед экспортом публикация автоматически сохраняется, поэтому каждый PNG соответствует сохранённой версии.

Горячие клавиши редактора: `Ctrl+S` сохранить, `Ctrl+Z` / `Ctrl+Shift+Z` отменить и повторить, `Ctrl+Shift+E` экспорт, `0` вписать, `1` 100%, `+`/`−` масштаб, `[` / `]` панели, `?` справка.

## Устройство проекта

Vite + Tailwind CSS v4 + модульный vanilla JavaScript, без фреймворков.

```
src/
  main.js                 точка входа, маршруты
  app/                    hash-роутер, оболочка (навигация)
  core/                   DOM-хелперы, события, id, утилиты
  domain/                 правила серий, время, драфт, построение снимков (чистые функции)
  data/                   IndexedDB (миграции), репозитории, медиа, герои, портреты, бэкап
  templates/              реестр шаблонов, общие примитивы, темы, фоны, шрифты, шаблоны tpl-*.js
  render/renderPoster.js  единый конвейер рендера: предпросмотр = экспорт
  export/                 PNG-экспорт (html-to-image) и встраивание шрифтов
  editor/                 редактор: store (undo/redo), предпросмотр, панели данных и оформления
  pages/                  обзор, команды, матчи, форма матча, публикации, шаблоны, настройки
  ui/                     иконки, контролы, тосты, модальные окна, меню
  styles/                 app.css (токены UI), poster.css (базовые стили постеров)
dev/poster-lab.html       стенд для визуальной проверки шаблонов (только для разработки)
tests/unit, tests/e2e     Vitest и Playwright
docs/                     требования, архитектура, модель данных
```

Подробнее: [docs/architecture/system-overview.md](docs/architecture/system-overview.md), [docs/architecture/data-model.md](docs/architecture/data-model.md).

## Шаблоны

| ID | Тип | Источник данных | Назначение |
|---|---|---|---|
| `match-announcement` | announcement | матч | анонс: MATCH, соперник, логотипы, время, турнир |
| `matchday` | matchday | 1–6 матчей | афиша игрового дня, карточки адаптируются к количеству |
| `win` | win | матч | победа выбранной («нашей») команды, счёт серии |
| `lose` | lose | матч | поражение выбранной команды |
| `series-result` | series-result | матч | нейтральный итог серии, включая ничью BO2 |
| `draft` | draft | матч + драфт карты | пики, баны, стороны, номер карты |

Все шаблоны собраны в базовом кадре 1080 × 1080 и экспортируются в 1080 и 1280 px. Экспорт 1280 рендерит тот же кадр с `pixelRatio`, поэтому раскладка совпадает с предпросмотром.

### Как добавить шаблон

1. Создайте `src/templates/tpl-<name>.js`, который по умолчанию экспортирует `defineTemplate({...})`. Обязательные поля: `id`, `type`, `version`, `name`, `source` (`match` | `matches` | `draft`), `base`, `render(ctx)`. Дополнительно: `exportSizes`, `texts`, `settings`, `defaults`, `validate`, `order`.
2. Соберите композицию из примитивов `templates/shared/primitives.js`: слои фона, затемнения, градиента и игрока, `teamLogo`, `fitText`, `dateLine`, `tournamentLine` и другие. Настройки возьмите из `commonSettings()` и дополните своими дескрипторами.
3. Файл подхватывается автоматически, редактор менять не нужно: панель оформления строится по дескрипторам.
4. Если изменение шаблона меняет внешний вид уже сохранённых постеров, оставьте старый модуль и зарегистрируйте новый объект с тем же `id` и большим `version`.

## Локальное хранение

- IndexedDB `dotaframe`, хранилища `teams`, `matches`, `drafts`, `projects`, `revisions`, `media`, `heroPortraits`, `settings`. Схема версионируется списком миграций в `src/data/db.js`.
- Изображения хранятся как Blob в `media` и **никогда не перезаписываются**: замена логотипа создаёт новый файл. `blob:` URL создаются только на время сессии.
- Снимок публикации (`project.data`) содержит все отображаемые значения и ID конкретных версий изображений. Открытая публикация рендерится только из снимка. Обновить его можно лишь явным действием «Обновить из матча».
- Данные живут только в этом браузере. Очистка данных сайта удалит их — делайте резервные копии в разделе «Данные и настройки».

## Экспорт и ограничения

- Формат PNG, размеры 1080 × 1080 и 1280 × 1280. После экспорта проверяется фактический размер файла.
- Перед растеризацией экспорт дожидается загрузки шрифтов (латиница и кириллица) и декодирования изображений.
- Прозрачный фон в текущих шаблонах не предусмотрен: все постеры фотографические и полноформатные.
- **Портреты героев и игровые изображения не поставляются.** Ассеты Dota 2 принадлежат Valve. Используйте только файлы, на которые у вас есть права, через раздел «Портреты героев». Без них показываются нейтральные заглушки с инициалами.
- Встроенные фоны процедурные (CSS/SVG). Фотографии фона и игроков загружает пользователь.
- Отдельные Figma-макеты шаблонов в разработке не использовались: доступа к закрытому файлу не было. Композиции построены по описанию референсов MATCH / WIN / MATCHDAY / LOSE.
- Навык Stageshow (benjitaylor/skills) рассчитан на React-демо и в основной проект не добавлен.

## Тестирование

- Юнит-тесты (`npm test`): правила счёта серий, валидация драфта, каталог героев, undo/redo, неизменность снимков, валидация резервных копий, утилиты.
- E2E (`npm run test:e2e`): сценарии в Chromium и Firefox — команды и логотипы, матчи и счёт, все шаблоны, сохранение и перезагрузка, неизменность истории, драфт, экспорт PNG с проверкой размеров, ошибочные файлы, длинные и кириллические названия.

Актуальный статус прогонов — в [docs/testing.md](docs/testing.md).
