# DotaFrame — концепция проекта

**Версия:** 0.1  
**Статус:** Проект документа  
**Этап:** Предпроектный анализ

## 1. Общие сведения

**Наименование:** DotaFrame

**Тип продукта:** Веб-приложение для автоматизированного создания графических материалов.

**Предметная область:** Киберспорт, Dota 2, SMM, графический дизайн.

DotaFrame — веб-сервис для создания графических публикаций о киберспортивных матчах Dota 2 на основе заранее подготовленных шаблонов.

## 2. Постановка проблемы

В процессе освещения киберспортивных соревнований SMM-специалистам и редакторам сообществ необходимо регулярно создавать однотипные графические материалы: анонсы, сообщения о начале матчей, драфты, результаты отдельных карт и серий.

Подготовка таких материалов в универсальных графических редакторах может требовать повторного ввода информации о командах, турнирах и результатах, а также ручной адаптации оформления.

**Продуктовая гипотеза:** специализированный генератор позволит сократить время подготовки повторяющихся публикаций благодаря шаблонам и повторному использованию данных матчей.

Гипотезу необходимо проверить на реальных пользовательских сценариях.

## 3. Цель проекта

Разработать веб-приложение DotaFrame, обеспечивающее создание графических материалов для освещения киберспортивных матчей Dota 2 на основе готовых шаблонов с возможностью настройки оформления и экспорта изображений.

## 4. Целевая аудитория

**Первая группа:** SMM-специалисты киберспортивных организаций.

Основная потребность — оперативное создание брендированных публикаций о матчах своей команды.

**Вторая группа:** редакторы киберспортивных СМИ и тематических сообществ.

Основная потребность — подготовка большого количества публикаций о различных командах, турнирах и матчах.

## 5. Ценностное предложение

DotaFrame объединяет данные киберспортивных матчей и графические шаблоны в едином рабочем процессе.

Предполагаемые преимущества:

- Повторное использование информации о матче.
- Быстрая подготовка нескольких типов публикаций.
- Единообразное оформление графических материалов.
- Возможность создания изображений без владения профессиональными графическими редакторами.
- Перспектива автоматического заполнения данных из API.

## 6. Основные пользовательские сценарии

**UC-01. Анонс матча**

Пользователь создаёт матч, указывает команды, турнир, дату и время, выбирает шаблон, настраивает оформление и экспортирует изображение.

**UC-02. Публикация результата**

Пользователь открывает существующий матч, вводит итоговый счёт, выбирает шаблон результата и формирует изображение без повторного ввода общей информации.

**UC-03. Публикация драфта**

Пользователь выбирает карту, указывает выбранных героев обеих команд и формирует графическое представление драфта. Сценарий запланирован для расширения продукта.

## 7. Предварительные границы MVP

В первую версию предлагается включить ручное создание матчей, выбор готовых шаблонов, настройку предусмотренных параметров оформления, предпросмотр, локальное сохранение данных и экспорт PNG.

Первые графические шаблоны: анонс матча и результат серии.

В MVP не входят свободное перемещение элементов, произвольное создание шаблонов, обязательная авторизация и автоматическая интеграция с платными API.

## 8. Предварительный технологический стек

**Интерфейс:** HTML5, Tailwind CSS.

**Логика приложения:** Vanilla JavaScript.

**Генерация изображений:** браузерный рендеринг с использованием библиотеки экспорта HTML в PNG, выбор которой требует проверки.

**Проектирование интерфейса:** Figma.

**Контроль версий:** Git и GitHub.

## 9. Критерии оценки полезности

Проверку продуктовой гипотезы предлагается проводить по следующим показателям:

- Время создания публикации.
- Количество действий для подготовки изображения.
- Возможность повторного использования данных.
- Корректность экспортируемой графики.
- Удобство работы с шаблонами.

Целевые значения показателей будут определены после первоначального тестирования.

## 10. Ограничения и риски

Основные риски:

- Недоступность внешних источников данных.
- Ограничения использования логотипов команд и изображений Dota 2.
- Проблемы экспорта шрифтов и изображений.
- Некорректное отображение длинных названий.
- Потеря локальных данных при очистке браузерного хранилища.

## 11. Перспективы развития

Предусматривается дальнейшее исследование автоматического получения матчей, графики драфтов, результатов отдельных карт, пакетной генерации и поддержки нескольких форматов публикаций.
